# Security Policy

## Supported Versions

NEXRYN is under active development. Security updates are provided only for the latest stable release branch and the current development branch.

| Version | Supported              |
| ------- | ---------------------- |
| 1.9.x   | ✅                      |
| 1.8.x   | ⚠️ Critical fixes only |
| 1.7.x   | ❌                      |
| < 1.7   | ❌                      |

Please upgrade to the latest supported version to receive security updates and patches.

---

## Reporting a Vulnerability

The security of NEXRYN is a top priority. If you discover a security vulnerability, please report it responsibly and avoid publicly disclosing details until the issue has been investigated and resolved.

### How to Report

Submit a detailed report through one of the following channels:

* Open a **private security advisory** on GitHub.
* Contact the maintainers directly via the designated security email address: **[security@nexryn.ai](mailto:security@nexryn.ai)**.

If a dedicated security email address is not yet available, please use GitHub's private reporting features instead of opening a public issue.

### What to Include

Please provide as much information as possible, including:

* A clear description of the vulnerability
* Steps to reproduce the issue
* Potential impact and affected components
* Proof-of-concept code, logs, or screenshots (if applicable)
* Suggested mitigations or fixes (optional)

### Response Timeline

The NEXRYN team aims to:

* Acknowledge receipt within **72 hours**
* Provide an initial assessment within **7 business days**
* Share progress updates regularly until resolution

Complex issues may require additional investigation time.

### Resolution Process

If the vulnerability is confirmed, the maintainers will:

1. Validate and reproduce the issue
2. Assess severity and impact
3. Develop and test a fix
4. Release a security update for supported versions
5. Publish a security advisory when appropriate

If the report is determined not to be a security issue, the maintainers will provide an explanation and may redirect the report to the appropriate issue tracker.

### Responsible Disclosure

Please do not:

* Publicly disclose vulnerabilities before a fix is available
* Share exploit details that could put users at risk
* Access, modify, or exfiltrate data beyond what is necessary to demonstrate the issue

We appreciate responsible disclosure and the efforts of security researchers who help improve the safety and reliability of NEXRYN.
